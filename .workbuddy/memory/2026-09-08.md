## 修复 Continue/Mobius 内置 embeddings（all-MiniLM-L6-v2）全面失败

症状：`Embedding: Failed to generate embeddings ... no available backend found`、
`Cannot find module 'onnxruntime-node'`、`ENOENT ort-wasm-simd-threaded.wasm`，
并导致扩展宿主卡死、聊天请求一直转圈无输出。

根因（三层，全都是**打包**问题，不是 AI 供应商问题）：
1. `continue/extensions/vscode/.vscodeignore` 里 `node_modules/**` 只放行了
   `@huggingface` 和 `@img`，`onnxruntime-node / -web / -common` 被剔除，
   而 `scripts/prepackage.js` 明明把它们复制到了 `node_modules/`。
   worker 里 `require("onnxruntime-node")` 因此失败。
2. 主包 extension.js 的 in-process 回退必然坏：esbuild `loader:{".node":"file"}`
   把 `require("../bin/napi-v3/<plat>/<arch>/onnxruntime_binding.node")`
   变成返回**路径字符串**，于是 `binding.InferenceSession is not a constructor`。
3. wasm 回退：@xenova/transformers 把 `wasmPaths` 设为 `<out>/dist/`，
   但打包时没人往 `out/dist/` 放 wasm → ENOENT。

改动：
- `continue/extensions/vscode/.vscodeignore`：为 onnxruntime-node/web/common 加放行规则。
- `continue/extensions/vscode/scripts/prepackage.js`：
  把 `onnxruntime-web/dist/ort-wasm*.{wasm,js}` 复制到 `out/dist/`；
  裁掉 `node_modules/onnxruntime-node/bin/napi-v3` 里非目标平台；
  `validateFilesPresent` 增加 onnxruntime 包与 `out/dist/ort-wasm-simd-threaded.wasm` 断言。
- `continue/core/llm/llms/TransformersJsEmbeddingsProvider.ts`：
  新增 `instanceError` 快速失败守卫（之前每个 chunk group 都重试构造 pipeline，
  2421 chunks ≈ 300 次失败重试，把扩展宿主拖死，这才是"请求一直转圈"的真凶）。

已用 esbuild 重建 out/extension.js、out/transformersJsEmbedWorker.js、
out/transformersJsGlmOcrWorker.js（源码树），验证：
- `node scripts/verify-minilm.mjs` → `[ OK ] MiniLM ONNX embed dims=384`
- 已安装端 `%LOCALAPPDATA%/Programs/Mobius/resources/app/extensions/continue`
  直接热修：补齐三个 onnxruntime 包 + `out/dist` wasm，
  实测 worker 产出 384 维向量成功。
