# Plan: Fix Cross-Project Skill Auto-Routing Leakage

## Root Cause
When an agent session runs in Mobius / VS Code, skills are gathered by `IPromptsService.findAgentSkills()`.
1. **Scope Over-Collection**: `PromptFilesLocator` gathers skills from:
   - Configured locations (`.agents/skills`, `.claude/skills`, `.github/skills`),
   - Parent repository walks up to repo root,
   - User home global directories (`~/.agents/skills`, `~/.claude/skills`),
   - Multi-root / recently opened workspaces in cache.
2. **Zero Workspace Scope Isolation**:
   In `continueSkillsContext.ts` (`buildContinueSkillsContext` and `buildContinueSkillsContextFast`), all skills returned by `findAgentSkills()` are loaded into `invocable` without validating whether local / project-specific skills (`skill.storage === PromptsStorage.local` or `.agents/skills`) actually reside within the active workspace root (`currentWorkspaceRoots`).
3. **Aggressive Auto-Skill Prior & Boost**:
   `isMobiusAutoGeneratedSkill` only checked if the file path string contained `/.agents/skills/auto/`, without checking workspace ownership. Skills from a different project (e.g. physics / wind farm CMS) received `MOBIUS_AUTO_SKILL_LEXICAL_PRIOR = 3` and `MOBIUS_AUTO_SKILL_FUSED_BOOST = 14`, plus `selectAutoRoutedSkills` guaranteed them a top-1 slot. When the user prompt contained generic development verbs (e.g. deploy, trace, debug, verify), these foreign skills won the top-3 auto-route slots and were injected into the agent's `<skill-context>`.

## Goal
Enforce strict workspace isolation in skill discovery and auto-routing so that:
1. Skills residing in `.agents/skills/` of other workspaces/projects are never auto-routed into the active workspace.
2. `isMobiusAutoGeneratedSkill` and `isMobiusAgentsFolderSkill` respect workspace boundaries, only granting priority boost to skills belonging to the current workspace.
3. Auto-routed selection (`selectAutoRoutedSkills`) only considers skills belonging to the current workspace or genuine global/builtin skills.

## Non-goals
- Disabling built-in skills or user-intentional global skills in `~/.agents/skills` (unless they are project-specific auto-skills).
- Changing prompt syntax for explicitly mentioned slash skills (`/skill-name`).
